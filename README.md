# Which parts to check before a vehicle's annual test

| Read | To |
|---|---|

The **MOT test**, named after the Ministry of Transport that introduced it, is the roadworthiness check that most vehicles in Great Britain must pass every year once they are three years old. A fleet manager pays for every MOT a vehicle fails: the retest, and the time off the road. We took every MOT test in Great Britain from May 2018 to the end of 2025, 308 million of them with the defects and advisories each recorded, and estimated, from a vehicle's past tests, the probability that its next one records each problem, to see whether checking the likeliest parts beforehand pays.

![Left: the money saved at p_crit = 0.1 from 2020 to 2025, rising from 10.6% to 13.2% for our model, from 5.0% to 8.7% for Repeat, and falling from 4.3% to 3.2% for Most popular. Right: the six groups of defects that save the most in 2025, engine oil leaks to registration plates, 33.8% to 23.9%, and the six that save the least, between 0.0% and −0.6%.](figures/money_saved.png)

## What we found

- **Our model would save a fleet manager 13.2% of what its MOT problems cost, and up to 34% on some groups of defects, such as engine oil leaks and rigid brake pipes**, where a missed problem costs ten times as much as a check. It beats re-checking what the last slot of tests found, which saves 8.7%, and saves more each year it is retrained. Test year 2025.
  **These figures are probably understated**, for the reasons in [`REPORT.md`](REPORT.md#caveats).
- **The saving stops where a missed problem costs two checks, a limit of the data rather than of the model**, because almost no vehicle in the MOT records is more likely than not to have any given problem, which is where a check would start to pay. Where a miss costs four checks, the model still saves 2.9%, while both simple rules lose money.
- **The model stays predictive as it is retrained each year**: its probabilities beat each problem's average rate in every year from 2020 to 2025, by more each year.
- **A simpler model, with rare makes and models pooled, is not better**, under a rule fixed before scoring, so we keep the first.

The recommendation, the evidence and the caveats are in [`REPORT.md`](REPORT.md).

## How it is built

- **The source files landed in Azure Blob Storage**, straight from the publishers, each checked against the SHA-256 computed as it landed, and an **Azure Function** checked the publisher's portal every day for new files.
- **Extraction that reads what Python cannot**: the 2022 and 2023 archives are compressed with Deflate64, read in constant memory and checked against each member's CRC-32.
- **Three file layouts read into one through Parquet**, every column as text, each file's rows checked against the rows read from its CSV.
- **A dbt build in DuckDB** in which every row of the files, 326 million tests and 673 million defect records, is either kept or removed by exactly one counted rule, with tests on every model, and a **training table** of 199 million rows: each vehicle's slot of tests, predicted from the slot before.
- **One logistic regression for each of 4,821 problems**, in three sizes set by how many cases each has, trained year by year on the years before only. The largest models, up to 114,060 inputs and 1.6 billion values, ran on an Azure virtual machine as sparse matrices; the smaller ones are fitted on counts, which gives the same weights as every row at a fraction of the cost.
- **Scored in money**: the share of what a fleet's problems cost that checking the flags saves, at any ratio of a check's cost to a missed problem's, and the **Brier skill** of the probabilities, recomputed from every saved model, against two simple rules and against the same models retrained on shuffled outcomes.
- **Every figure in `DATA.md` regenerated by a file in `evidence/`**, every figure in `REPORT.md` by [`analysis/01_next_test.py`](analysis/01_next_test.py) and its image by [`src/motrisk/plots.py`](src/motrisk/plots.py), and tests on every push.

## Running it

You need Python 3.12 or later and a C compiler with Python's headers, which `zipfile-deflate64` needs to build. The full build, the largest models and their rescoring need about 32 GB of memory; the rest ran on a computer with 7 GB. The steps in Azure, `azure/`, `function/`, `src/motrisk/fetch.py` and the `azure` modes below, ran on resources since deleted; `DATA.md` records what they did.

**Install** in a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,transform]"
```

**Download** the 17 files into `data/raw/`, about 28 GB, and check each against the SHA-256 recorded when we fetched it:

```bash
mkdir -p data/raw
tail -n +2 data/fetch_log.tsv | cut -f5 | xargs -n 1 curl -fLO --output-dir data/raw
tail -n +2 data/fetch_log.tsv | awk -F'\t' '{print $4 "  data/raw/" $2}' | sha256sum -c
```

**Extract and convert** the CSVs into `data/extracted/` and then `data/parquet/`:

```bash
python src/motrisk/extract.py local
python src/motrisk/convert.py local
```

**Build** the staged tables and the training table into `data/processed/mot.duckdb`, then export what the models read:

```bash
(cd transform && dbt build)
python src/motrisk/export.py
```

**Score the baselines, then fit and score the models**, the folds in order, since each starts from the one before:

```bash
python src/motrisk/baselines.py
for y in 2019 2020 2021 2022 2023 2024 2025; do
  python src/motrisk/small_models.py count $y
  python src/motrisk/small_models.py count $y --shuffled
done
for y in 2020 2021 2022 2023 2024 2025; do
  python src/motrisk/small_models.py fit $y
  python src/motrisk/small_models.py fit $y --shuffled
  python src/motrisk/full_models.py $y
  python src/motrisk/full_models.py $y --shuffled
  python src/motrisk/rescore.py small $y
  python src/motrisk/rescore.py small $y --shuffled
  python src/motrisk/rescore.py full $y
done
python analysis/01_next_test.py
```

The second model runs the same steps with `--encoding pooled` on `fit`, `full_models.py` and `rescore.py`, then `python analysis/01_next_test.py --encoding pooled`. Each file's header says what it writes and which checks stop it.

**Draw the image** in `REPORT.md` from those results:

```bash
pip install -e ".[figures]"
python src/motrisk/plots.py
```

**Test:**

```bash
pytest
```
